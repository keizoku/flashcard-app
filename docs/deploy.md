# インターネットに公開する（Vercel ＋ Neon、無料）

手元の Docker ではなく、インターネット上で動かして、外出先やスマホからも使えるようにする手順です。

- アプリ: [Vercel](https://vercel.com/)（無料の Hobby プラン）
- DB: [Neon](https://neon.com/)（無料の PostgreSQL）

アカウントの作成、パスワード・キーの入力は、自分で行ってください（ここに書くのは手順だけです）。

## 無料の枠（2026年11月に確かめた内容。変わることがあるので、始める前に各サイトで確かめる）

| | 無料の枠 | このアプリで気をつけること |
| --- | --- | --- |
| Vercel Hobby | 個人の非商用の利用だけ（お金をいただくサービスにするときは、有料の Pro プランが要る）。非公開のリポジトリでも使える。1回の処理は最大300秒 | 絵を自動で作る処理は最大90秒待つので、単語帳の画面は `maxDuration = 120`（秒）にしてある |
| Neon Free | 1プロジェクトに 1GB の保存容量、月 100 CU 時間の計算。超えると月末まで止まる（料金はかからない） | 場面の絵は DB に入るので、容量を多く使う（1枚 数百KB）。しばらく使わないと DB が眠り、最初の表示が数秒遅れる |

## 1. Neon で DB を作る

1. Neon にサインアップして、プロジェクトを作る。リージョンは日本に近いところ（例: AWS Asia Pacific (Singapore) か Tokyo があればそれ）を選ぶ
2. 「Connect」で、接続の文字列（`postgresql://…?sslmode=require`）をコピーする。
   **「Connection pooling」を有効にした文字列（ホスト名に `-pooler` が付く）を使う**（Vercel はアクセスのたびに接続するので、接続が増えすぎないように）

## 2. （使っているデータを移すとき）手元の DB を Neon に写す

新しく始めるなら、この手順はいらない。写すなら、**Vercel に初めて公開する前に**、空の Neon の DB に写す
（先に公開すると、Vercel のビルドが空のテーブルを作ってしまい、写すときにぶつかる）。

```bash
docker compose exec -T db pg_dump -U flashcard --no-owner --no-acl flashcard > flashcard-dump.sql
```

```bash
docker run --rm -i postgres:17 psql "ここに Neon の接続の文字列" < flashcard-dump.sql
```

- `flashcard-dump.sql` には学習データとパスワードのハッシュが入っているので、写したら消す。Git には入れない
- 手元のデータはそのまま残る。写したあとは、手元と Neon のデータは別々に増えていく

## 3. Vercel に公開する

1. Vercel に GitHub のアカウントでサインアップし、「Add New → Project」で `flashcard-app` のリポジトリを選ぶ。
   Vercel にこのリポジトリを読む許可を与える（GitHub の画面で、許可するリポジトリを `flashcard-app` だけにする）
2. Framework は Next.js（自動で選ばれる）。ビルドのコマンドは変えない（`package.json` の `vercel-build` が使われ、**先に DB のマイグレーションを当ててから**ビルドする）
3. 「Environment Variables」に入れる:

| 名前 | 値 |
| --- | --- |
| `DATABASE_URL` | Neon の接続の文字列（`-pooler` の付いたもの） |
| `APP_URL` | 公開した URL（例: `https://flashcard-app-xxxx.vercel.app`）。リダイレクト先と、ログインの Cookie を HTTPS だけにするのに使う。パスキーもこのドメインに結びつく（URL を変えると、登録したパスキーは使えなくなる）。入れ忘れても、Vercel が教える本番の URL（`VERCEL_PROJECT_PRODUCTION_URL`）を使う（`lib/appUrl.js`）。独自のドメインを使うときは、必ず入れる |
| `ADMIN_USERNAMES` | **自分のログインの ID**。管理者の画面（`/admin`。ユーザーの数・使われ方の集計）を見られる人。カンマ区切り。空なら、だれも見られない（[auth.md](auth.md#管理者libadminjs)） |

メールは送らないので、SMTP の設定はいらない。前に入れていた `ALLOWED_EMAILS`・`ADMIN_EMAILS`・`SMTP_*`・`MAIL_FROM` は消してよい（使っていない）。

4. 「Deploy」を押す。初めは URL がわからないので、公開されたら `APP_URL` にその URL を入れて、「Redeploy」する
5. 「Settings → Functions → Function Region」を、Neon と同じか近いリージョン（例: Tokyo `hnd1`）にする。離れていると、画面の表示が遅くなる

これで、`main` にプッシュするたびに自動で公開し直される。

## アカウントを作る・ID を変える（管理用の道具）

どれも、ターミナルで `flashcard-app` フォルダの中で実行する（手元の Docker が動いていること）。
このチャットの入力欄などではなく、ふつうのターミナル（Mac の「ターミナル」など）で実行する。
はじめに、つなぐ DB の接続の文字列を聞かれる: Neon の「Connect」でコピーしたもの（Database は `flashcard`。プーリングはどちらでもよい）。画面には出ない。
手元の DB には触れない（毎回、つなぐ先を聞く。中身は `lib/userAdmin.js`）。

### だれかに試してもらうアカウントを作る

```bash
docker compose exec app node scripts/create-user.mjs
```

1. ID と、パスワード（8文字以上）を2回入れる（パスワードは画面には出ない）
2. 「アカウントを作りました」と、復旧コードが出る
3. 相手に、URL・ID・パスワード・復旧コードを伝える（パスワードは、ほかと別の手段で伝えると安全）

- すでにある ID を入れると、パスワードを作り直すかを聞かれる（`y` で作り直し、その人のログインはすべて切る）。
  相手がパスワードも復旧コードもなくしたときにも使う
- 相手はログインしたあと、アカウントの画面で自分のパスワードに変えられる
- だれでも `/signup` から登録できるので、ふつうは相手に登録してもらえばよい

### ID を変える

メールアドレスから ID に切り替えたとき（migration 025）、今までのアカウントは、メールアドレスがそのまま ID になっている（今までどおりログインできる）。好きな ID に変えたいときに使う。

```bash
docker compose exec app node scripts/rename-user.mjs
```

- アカウントの一覧（ID・登録した日・単語帳の数・カードの数）が出るので、どれが自分か確かめてから、今の ID と新しい ID を入れる
- パスワード・データ・パスキーはそのまま。次から新しい ID でログインする
- 変えたら、アカウントの画面で **復旧コードを作る**（切り替える前からのアカウントには、まだない）
- 管理者にするなら、Vercel の `ADMIN_USERNAMES` も新しい ID にして「Redeploy」する

## テスト用のアカウントを、最初の状態に戻す

試してもらったアカウントを、登録した直後（トップに「はじめの4ステップ」が出る状態）に戻す。

```bash
docker compose exec app node scripts/reset-user.mjs
```

- 接続の文字列（画面には出ない）と ID を入れると、消す内容を見せてから、**同じ ID をもう一度**入れてもらう。
  違うものを入れるか、Enter だけなら何も消さない（まちがって自分のデータを消さないように）
- 消すもの: 単語帳・カード・学習の記録・レベル設定・「知ってる」の語・勉強時間。「はじめの4ステップ」を閉じた印も消す
- 残すもの: アカウント・パスワード・ログイン
- 元に戻せないので、自分の ID を入れないよう気をつける
- 「字幕をコピーする方法」を閉じたことはブラウザの Cookie に残っているので、最初の表示にしたいときは、そのブラウザのこのサイトの Cookie を消すか、シークレットウィンドウで開く

## 公開したあとに気をつけること

- **だれでもユーザー登録できる。** URL を知っている人は登録して使える（データは人ごとに分かれている。[auth.md](auth.md)）。
  いたずらで大量に作られないように、同じ接続元からの登録は1日5回まで
- **「登録せずに試す」（おためしユーザー）も、だれでも使える。** 1日で自動で削除され、作れる量にも制限がある（[auth.md](auth.md#おためしユーザーlibguestjsapptry)）。
  削除は `vercel.json` の Cron（毎日 3時ごろ、日本時間）が `/api/cron/cleanup-guests` を呼んで行う。Hobby の Cron は1日1回で、時刻はその1時間のどこか。
  そのため、期限が過ぎてから実際に消えるまで、最大で1日ほど残ることがある（期限が過ぎた人は、消える前でも使えない）
- **ブランチをプッシュしたときのプレビューも、同じ DB を使う。** プレビューのビルドでもマイグレーションが当たるので、テーブルを変えるブランチは注意する
- 絵の自動生成（Pollinations）・動画の題名の取得（YouTube）は、Vercel のサーバーから外のサービスにつなぐ。サービスの都合で断られることがある
- 手元の Docker の環境は今までどおり使える（`DATABASE_URL` は手元の DB のまま）
